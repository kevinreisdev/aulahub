# Data Model — backend_journey

## Overview
An online-classes platform API. Teachers create courses made of lessons,
students enroll in courses and watch the lessons, and admins manage the system.

## Entities

### User (base class)
| Attribute     | Type     | Required | Notes                                  |
| ------------- | -------- | -------- | -------------------------------------- |
| id            | int      | yes      | unique, generated by the system        |
| first_name    | str      | yes      |                                        |
| last_name     | str      | yes      |                                        |
| email         | str      | yes      | unique, stored in lowercase            |
| password_hash | str      | yes      | never store the plain password         |
| role          | str      | yes      | one of: "student", "teacher", "admin"  |
| is_active     | bool     | yes      | default True; False = deactivated user |
| created_at    | datetime | yes      | set automatically on creation          |

**Validation rules**
- first_name and last_name: min 3 characters, max 50 characters
- email: must contain "@" and a "." after it
- password (before hashing): at least 8 characters
- role: must be one of the allowed values
- a user is never deleted, only deactivated (is_active = False)

**Inherited by:** Student, Teacher

---

### Student (inherits User)
| Attribute | Type | Required | Notes                 |
| --------- | ---- | -------- | --------------------- |
| role      | str  | yes      | always "student"      |

No extra attributes. The class exists for behavior (e.g. enrolling in a course).
Its courses come from the Enrollment entity.

**Validation rules**
- role is set automatically to "student" (cannot be changed)

---

### Teacher (inherits User)
| Attribute | Type | Required | Notes                          |
| --------- | ---- | -------- | ------------------------------ |
| role      | str  | yes      | always "teacher"               |
| bio       | str  | no       | short description, default ""  |

**Validation rules**
- role is set automatically to "teacher" (cannot be changed)
- bio: max 500 characters

---

### Admin
Not a separate class: an admin is a User with role = "admin".
It has no attributes of its own, so a subclass would add nothing.

---

### Course
| Attribute    | Type     | Required | Notes                              |
| ------------ | -------- | -------- | ---------------------------------- |
| id           | int      | yes      | unique, generated by the system    |
| title        | str      | yes      |                                    |
| description  | str      | no       | default ""                         |
| teacher_id   | int      | yes      | the Teacher who owns the course    |
| is_published | bool     | yes      | default False; students only see published courses |
| created_at   | datetime | yes      | set automatically on creation      |

**Validation rules**
- title: not empty, min 10, max 100 characters
- teacher_id must belong to a User with role "teacher"
- a course can only be published if it has at least 1 lesson

---

### Lesson
| Attribute        | Type | Required | Notes                                  |
| ---------------- | ---- | -------- | -------------------------------------- |
| id               | int  | yes      | unique, generated by the system        |
| course_id        | int  | yes      | the Course this lesson belongs to      |
| title            | str  | yes      |                                        |
| video_url        | str  | yes      |                                        |
| position         | int  | yes      | order inside the course (1, 2, 3...)   |
| duration_minutes | int  | yes      |                                        |

**Validation rules**
- title: not empty, max 100 characters
- video_url: must start with "http://" or "https://"
- position: greater than 0, unique inside the same course
- duration_minutes: greater than 0

---

### Enrollment
| Attribute   | Type     | Required | Notes                                         |
| ----------- | -------- | -------- | --------------------------------------------- |
| id          | int      | yes      | unique, generated by the system               |
| student_id  | int      | yes      | the Student enrolled                          |
| course_id   | int      | yes      | the Course                                    |
| status      | str      | yes      | one of: "active", "completed", "cancelled"; default "active" |
| enrolled_at | datetime | yes      | set automatically on creation                 |

**Validation rules**
- a student can't enroll twice in the same course (student_id + course_id is unique)
- a student can only enroll in a published course
- status must be one of the allowed values

## Relationships
- Teacher 1 ── N Course
- Course 1 ── N Lesson
- Student N ── N Course (through Enrollment)

## Permissions (who can do what)
| Action                         | Student            | Teacher            | Admin |
| ------------------------------ | ------------------ | ------------------ | ----- |
| List published courses         | yes                | yes                | yes   |
| View lessons of a course       | only if enrolled   | only own courses   | yes   |
| Create course                  | no                 | yes                | yes   |
| Edit / publish course          | no                 | only own courses   | yes   |
| Create / edit lesson           | no                 | only own courses   | yes   |
| Enroll in course               | yes                | no                 | no    |
| Cancel enrollment              | only own           | no                 | yes   |
| Deactivate user                | no                 | no                 | yes   |

## Decisions
- Relationships store ids (student_id, course_id), not whole objects.
  This matches how the database will work (foreign keys) in Phase 4.
- Nothing is hard-deleted at first: users are deactivated, enrollments are cancelled.
